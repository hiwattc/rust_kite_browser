# Kite 계획

## 목표

1. 크롬처럼 쓸 수 있는 가벼운 Windows/macOS 브라우저 (termtree와 같은 Tauri v2 스택)
2. **스포트라이트**(Ctrl+Shift+P): 탭·북마크·기록·명령 통합 검색
3. **MCP 서버**: Claude Code가 Playwright MCP처럼 이 브라우저를 조작
4. 이후 기능을 계속 붙일 수 있는 구조 (명령은 팔레트 명령 + 단축키 표 + MCP 도구 세 곳에 같은 방식으로 추가)

## 핵심 설계 결정

| 항목 | 결정 | 이유 / 대안 |
|---|---|---|
| 엔진 | OS 웹뷰 (WebView2 / WKWebView), 탭마다 웹뷰 하나 | termtree와 같은 스택, 설치 파일 작음. 대안 CEF(진짜 Chromium 양쪽 동일, CDP 사용 가능)는 바이너리 수백 MB·빌드 복잡 → 필요해지면 재검토 |
| 창 구성 | 창마다 `ui(-n)` / `palette(-n)` 웹뷰, 탭은 `tab-<id>`. 탭을 다른 창으로 옮길 때 웹뷰를 `reparent`(페이지 상태 유지) | 팔레트가 페이지 위에 떠야 해서 별도 웹뷰. 열 때 맨 앞으로(macOS reparent, Windows SetWindowPos) |
| 상태 | Rust가 탭 상태 소유, UI는 그리기만 | MCP와 UI가 같은 상태를 봄 |
| 자동화 통로 | Rust → `eval_with_callback` (결과 JSON), async는 폴링 | 웹 페이지에 IPC를 열지 않음 |
| 페이지 → 앱 | `content_event`(단축키·URL 변경 알림) 하나만 허용 | 단축키가 페이지 포커스에서도 동작하려면 필요. 값은 믿지 않음 |
| 단축키 | `keymap.rs` 표 하나, `e.code` 기준 | 한글 IME 상태에서도 동작 |
| 로딩 완료 | 페이지 로드 이벤트 + 감시(readyState·URL 일치) | WKWebView가 끝 이벤트를 안 줄 때가 있음(리다이렉트, 복원 탭) |
| 저장소 | SQLite 한 파일 | 북마크·기록·설정·세션 |
| 내부 페이지 | `kite://settings` 등은 앱 페이지를 탭 웹뷰에 띄움. 권한은 `capabilities/internal.json`(로컬 페이지만), 앱이 직접 이동할 때만 열림(`internal_pass`), 프레임 안에서는 동작 안 함, 에이전트 스크립트 금지 | 크롬의 chrome:// 와 같은 역할 |

## 검증한 것 (macOS, 2026-11-22)

- MCP로 example.com 이동 → 스냅샷 → 스크린샷, httpbin 폼 채우기·제출 결과 읽기
- 위키백과: 검색어 입력+제출(리다이렉트) → 링크 클릭 → 뒤로 → 요소 스크린샷, 콘솔/네트워크 기록
- 페이지 포커스 상태에서 Ctrl+Shift+P / ⌘T, 팔레트가 페이지 위에 뜸, `햣`→GitHub, `qntks`→부산
- Windows: `cargo xwin clippy` 통과(실기 실행은 아직)
- (v0.2.0) 접속 불가: 없는 주소(dns)·닫힌 포트(refused)·만료 인증서(cert) 감지, expired.badssl.com 계속 진행 후 열림·self-signed는 계속 차단. 홈: 섹션 추가·이동·크기 조절·아이콘 섹션 간 이동·저장

## 알려진 문제 / 메모

- 세션 복원 시 POST 결과 페이지는 GET으로 다시 열림(405 등).
- 팔레트 웹뷰는 사각 모서리(웹뷰 투명 처리는 플랫폼별로 불안정해서 보류).
